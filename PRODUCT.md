# Product

## Register

product

## Users

Customers use a desktop computer to request vehicle maintenance, understand the estimate, and decide how much additional work to authorize. Mechanics and administrators use the same application to coordinate work. Assume a normally lit home or workshop office, with users who need legible controls and a clear next action.

## Product Purpose

Car Servicinator 3000 connects customers, their vehicles, and workshops. A successful request records the selected catalog services with a complete estimate and explicit permission for additional work. Unavailable data must never look like a valid zero-price estimate.

## Brand Personality

Calm, professional, clear. The user selected this direction for the interface refresh. Keep the existing product name, use direct language, and explain what happens next without technical implementation details.

## Anti-references

Avoid emoji-heavy forms, rainbow action buttons, decorative gradients, excessive shadows, debug labels, and densely packed controls. Do not present a price-loading failure as an empty but usable catalog.

## Design Principles

- Make the next action and the consequence of submitting obvious.
- Keep the estimate visible and consistent with the selected services.
- Explain unavailable data and offer a useful recovery action.
- Preserve familiar desktop controls, keyboard access, and visible focus.
- Use the same visual vocabulary across login, dashboard, and request creation.

## Accessibility & Inclusion

Use readable system typography, explicit control labels, keyboard-operable native controls, wrapping error text, and sufficient text contrast. Do not rely on color alone for selection or validation. Keep the full request form reachable at the application's minimum window size. Avoid decorative motion.
